# 网页 ChatGPT 协作（规划 / 审查 / 产出素材）

角色分工：**网页版 ChatGPT 出方案、做独立审查，也能产出图片/视频素材；本机 agent 负责执行、
取回与核验；用户保留最终授权**。本机 agent 不替它做设计决策，也不把没核过的产出当成果交付。

整套东西靠三件东西连起来：一个**只读 MCP 桥**（把当前工作区暴露给网页端，它自己按需读文件，
任何人都不许粘贴文件内容）、一个**专用浏览器实例**（登录态在里面，agent 通过 CDP 真正操作页面）、
以及**本 skill 里的流程与判据**。桥怎么装见 `references/bridge-setup.md`；
两个系统的差异见 `references/cross-platform.md`。

本 skill 是给 **Hermes** 用的：流程、判据、坑表都假定你有一双能操作浏览器的手
（`browser_exec` + CDP，见下节）。没有浏览器控制权时只有"首次接入"能靠手动路径完成，
日常协作仍然需要浏览器控制——这不是可选项。

## When to Use（触发条件）

- 用户口令（任一即触发）：「让 GPT 看一下 / 问问 GPT / 问问 ChatGPT」「先让 GPT 出个方案」
  「让 GPT 审一下 / 让 GPT 盯着做」「让 GPT 画张图 / 配图让 GPT 画」。
  这类简短口令**不要再问「要不要咨询网页端」**，直接按对应模式走。
- 反向触发（立即停止网页端协作，不要反复确认）：「你自己做」「别叫 GPT」「不用 GPT 了」。
- **默认就是完整闭环**：复杂/多步骤任务 → 网页端出方案 → 本机执行 → 结果交网页端独立审查 →
  按意见改到通过。简单问答、一步小操作直接做，不要为仪式感等一轮。
- 用户要网页端产出素材（生图/生视频）时：按「素材取回与验真」取回并验真。

## 入口与环境

- **命令入口**：`node <c2c检出目录>/bin/c2c.js <cmd> -w <workspace> --json`
- **浏览器能力**：Hermes 的 `browser_exec` —— `js()` / `cdp()` / `click_at_xy()` /
  `switch_tab()` / `capture_screenshot()`；它接的是一个**原生启动**的 Chrome
  （独立 user-data-dir + `--remote-debugging-port=<PORT>`，配置见 `references/bridge-setup.md`）。

例外：`c2c record` **不接受 `--json`**，它只回一行中文确认。
机器级命令（`update-check`、`sandbox-allow`、`prefs`、`tunnel login`）**不要带 `-w`**。

**先读本机状态，不要重新发现**：绑定关系（工作目录、连接器名、ChatGPT 项目/对话）、
浏览器接入方式、环境改动清单都在状态文件里 ——
`${HERMES_HOME:-$HOME/.hermes}/handoffs/chatgpt-web-state.md`
（Windows：`%USERPROFILE%\.hermes\handoffs\chatgpt-web-state.md`）。
第一次接入时由 agent 按 `references/bridge-setup.md` 建好并写进这个文件。

**动手前先枚举协作浏览器的标签页**：`cdp('Target.getTargets')` 过滤 `type=='page'`，
打出 targetId / title / url。里面常有**上一轮（可能中途断掉、没交付）的对话和已生成好的产物**——
标题/URL 就能认出来。此时先按 `references/media-export.md` 把现成的图取回，**不要重发同一条需求**：
重发生成的是另一张图，白烧一轮，而用户要的是能拿到手的成品。汇报时说明它来自早前那一轮，
并与本次新出的图分清楚。

## 每轮流程

1. `doctor` 先行：**不绿就不要打开 ChatGPT、不要发 `[C2C]` 消息**；`chatgptRepair.needed` 时先修连接器。
   **doctor 的连接器记账会漂移**：它比较的是自己记录的地址，第一次 doctor 把记录刷成新地址后，
   第二次就会报 `needed:false`，哪怕 ChatGPT 上的连接器仍指着已死的旧地址。连接器的真实地址以
   ChatGPT「管理」面板里显示的 URL 为准，或用一次真实的 `workspace_info` 调用验证——不要只看 doctor 结论。
2. 只在**本任务自己的对话**里工作（不要动 `c2c session` 里其它任务的记录），
   且**每个新任务开一个全新对话**——规则见「会话管理」。
3. 发一条短任务说明：目标、范围、限制、成功标准；明确要求它用指定连接器自己读文件，
   **不接受任何人粘贴文件内容**。范围默认收窄：只新建本次任务自己的目录与文件，
   不改工作区其它已有资产（既写进任务说明，也约束自己）。
4. 等完整回复，判断是否可执行；**不盲从**网页建议，不做超出用户授权的操作。
5. 本机执行并核验；用 `c2c record` 记录执行摘要与允许发布的输出——不粘贴代码、diff、日志或凭据。
6. 发 EXECUTED 要求独立审查；收到**有证据**的修改建议就修，通过后再向用户汇报。
7. 每轮留检查点，避免页面慢/超时导致重复发送或重复执行。网页失效时**明说「尚未完成咨询」**，
   不要假装已得到审查。

## 只传背景与需求，不要替它下限定（用户反复纠正过，优先级仅次于「先交材料再动手」）

用户原话：**"你根本不用限定这么多啊，你就把我给你的需求和他说就行了，它的模型能力是你的好几倍，
你还在乱指挥干啥"**、**"以后你只阐述背景，不要限定要求"**。

- **要写**：背景（这是什么材料、用来干什么）、用户的需求、必要的上下文（工作区/限制条件）。
- **不要写**：版式/字号/配色/每页几条要点/字数上限/图形类型这类你把手的具体规格，
  **也不要自己编一套验收标准**。那些是它的专业范围；你替它定，只会得到一个拘手拘脚的次品，
  还白烧轮次。
- 实证：只发一句需求（附件是论文＋要 5 张科研 PPT 生图），它自己就规划了
  "先核对论文方法与数据 → 按研究背景-耦合框架-情景设计-主要结果-结论与局限组织"，
  而且首轮自己发现"五页拼版不符合一页一张完整图片"并改为逐页生成——**写死规格时这不会发生**。
- 交付风格/验收标准确实需要固定时，用**用户给的参考稿**当标准（那是唯一权威），不要自己发明。
- 口令只给类型、没给题材时（如「帮我用 gpt 画一张摄影图」）：**先用一次 `clarify` 把题材拿下来**
  （推荐项放第一）。题材决定整张图是什么，替它挑题材等于白烧一轮；拿到题材后仍只发
  「题材 + 背景 + 需求」，构图/光线/风格/比例全部交给它定——**问用户要题材不算「替它下限定」**。

## 先交材料再动手（用户明确的职能划分，优先级最高）

用户原话：**"你只是用来行动的，真正出主意的大脑是 GPT"**。收到任务、尤其是收到材料文件时，
**第一步就是把材料交给网页端，要到一份"可实现的方案"，再按方案在本机执行**。

- 不要自己先探索、先试做、先选技术路线。用自己的判断力替代它的规划，结果是白烧好几轮——
  实测：自己估字号、去翻模板库、换转换器、从头手搓设计，全被否，最后仍是"先要方案"这条路才对。
- 交付材料时**把文件真的挂进对话**（不只是描述）：配方见
  `references/uploading-files-to-web-chatgpt.md`。
- 方案到手后**按它执行**，并把"AI 负责什么、程序负责什么"落到实现里：内容与结构交给模型，
  字号/颜色/坐标这类视觉参数交给**冻结的规格与程序计算**，不要每页临场决定。

## 交付前必须先「以专家身份自审一遍」（用户定死的规矩，每轮都要写进提示词）

用户原话：**「你以后提示词加一个做完任务以一个专家来审查一遍」**。不要等它交完再补，
**发任务时就写进要求**：

> 交付前先切到「独立审查专家」的身份，把本轮每一件产物逐条对回事实来源（背景文件／数据／材料），
> 无据的内容、做错的部分、信息过载一律自己驳回重做，**过检再交**，并写出审查结论与依据；
> 最后明确说「哪几件是过检的成品」。

实测有效：它自己连续驳回了 3 批图——「引入了源文件里不存在的 Kubernetes／RAG／数据库」、
「擅自加入 CLI／API Clients」、「把 CDP 画成走 named tunnel」——**没把废稿冒充成成品**。
宁可多烧几轮，也不要它交一堆看着像样的错图。
自审不等于免检：本机仍要按 `scripts/verify_asset_origin.py` ＋ 对着组件/标签清单逐条核。

### 拿不准是否达标：交叉评审

不要在同一个会话里反复嘀咕：把它的产出（图/文）发到**另一个新会话**，让它以评审者身份给意见，
再把意见带回原会话让它改。同一个模型换一个"不带原会话上下文"的身份批自己上一轮的产物，
比在原会话里来回问有效。**它自己判废时不要反驳**——判废理由通常是对的（本机看图核对即可验证）。

## 长文稿类任务：背景进工作区 → 它写 → 本机成文 → 它审 → 定稿（实测有效）

适合"写一份研讨稿/报告/方案"这类任务（区别于生图和精确架构图）。

- **背景材料写成工作区里的 md 文件，让网页端用连接器自己读**，不要粘贴。它读得很准
  （会自报读到的行数），并会主动把"材料里没有的事实"标成假设——比写一堆限定词有效得多。
- **审查至少跑两轮**：第二轮它才会去翻正文之外的角落（术语表、附录、脚注、引用）。
  实测：第二轮给"有条件通过"并指出 5 处"正文改了、附录没改"的漏改，第三轮才"定稿"。
  只跑一轮就交付，附录里的旧表述会留在成品里。
- **取回复要切片，不要拿 `body.innerText` 全量**：里面混着"跳转到内容 / 分享 / 最新一条回复"
  等外壳文本。干净回复 = 文本里 `'ChatGPT 说：'` 之后到 `'ChatGPT 可能会出错'` 之前那一段。
- **长回复是分段流式写的**：某一段长度几分钟不变，很可能它在用连接器读文件，别当卡死重发。
  完成判据用"最后一段长度稳定 + 页面出现『回答已完成』"，不要只看"你说："计数（会滞后）。
- 本机把这个对话的成果写成本地文件后再发回去审，比在同一轮里来回追问好。

## 会话管理：一个任务一个对话（用户要求）

**为什么**：同一个对话里上下文越堆越长，它的判断会变糊（用户原话「上下文太长会降智」）。

- 每开始一个**新任务**（或换工作区）→ 在网页端开**全新对话**，不要在旧对话里接着加。
- 同一任务内的多轮复审（EXECUTED → 审查 → 再 EXECUTED）**留在同一个对话**；只有跨任务才重开。
- 新对话的第一条消息必须**自包含**：目标 / 范围 / 限制 / 成功标准（它没有任何历史）。
- 上一个任务若对本次有用，用**一条短消息交接**（「上一个任务已完成：<一句话结论>。本次是新任务：…」），
  不要整段粘贴旧内容。
- 对话聊得过长、它开始重复或变糊涂时，就地开新对话并把当前状态写成交接消息。

**别信「导航到 `https://chatgpt.com/` 就是新对话」**：在同一个标签里这样做，客户端路由可能把你带回
**上一个对话**（实测：`location.href` 已是新的 `/c/<id>`，但 `document.title` 还是旧会话标题、
DOM 里还是旧会话的消息）。发第一条消息**前**核对三件事：对话 id 变了、`document.title` 变了、
DOM 里没有上一轮的消息。不放心就直接点侧边栏「新聊天」。

## 素材取回与验真（要交付成品时读 `references/media-export.md`）

- 提要求时明确写「请真正调用图像生成工具，不要用代码或 SVG 绘制」。
- **判据只认页面里 `img[src^="blob:"]` 的图数 > 0**，不要拿正文里的「回答已完成」当结束信号
  （实测它在 blob 图数为 0 时就已出现）。图出现后再多等一轮再取字节。
- **长对话里页面会虚拟化**（可见 blob 图只有 4–6 张且波动）：判完成改用
  **「最后一张 blob 图的 `src` 变了」**，取图只取最后一张 + sha256 去重。
- **一批多张时反着来**：枚举所有 blob 图、用「sha256 没见过」筛新图——
  不要按 `aria-label` 或「取最后 N 个」（DOM 顺序 ≠ 时间顺序，会拿到上一轮的旧图）。
- 取回**原文件字节**，不是截图；落盘后跑 `scripts/verify_asset_origin.py <file>`
  （字节数 / sha256 / 容器结构 / C2PA 出处）。**截图永远不算成品**，只能当导航证据。
- 落盘命名用**「已保存计数器」**，不要用页码索引（某一轮超时没取到就会整体错位）。
- 导入工作区走 `c2c asset import`（只写新路径，**绝不覆盖**）；导完把工作区文件的 sha256
  与本地源文件对一遍再汇报。
- 给用户看大图时先出缩略图，但**必须明说那是缩略图**并同时给原图路径。
- 连续出十几张（如 PPT 逐页生图）走 **`references/slide-image-pipeline.md`**，
  配套辅助函数在 `scripts/gen_helper.py`（判完成、取字节、去重、命名计数器都在里面）。

## 文档配图：分工与风格（用户偏好）

- **所有插画都交给网页端图像模型**，包括架构图 / 流程图 / 分层图这类结构化图；
  不要自己用 HTML/CSS 渲染再截图充当配图。只有用户点名要「精确图」时才自绘。
- **一张图只讲一件事**（用户原话：「它是一个图塞了四五个子图，信息密度太大了」）：
  要 4 张就是 **4 张独立图片**，每张画布只放一张完整的图；**禁止 a/b/c/d 拼版**。
  「几张、每张切什么」仍由它定；但「一图一事、多张就多张独立图」必须写进要求。
- 默认风格「剪纸艺术」：多层纸雕 + 层间投影阴影 + 纸张纤维质感 + 手工剪边 + 浅色背景；
  颜色要**鲜艳多色**（不同层/不同模块各一色），不要同色系单色。
- 图内**要写字**：在提示里**逐字给出标签原文**，并要求「汉字正确、工整、不要多余的字、不要乱码」，
  每张只放 1–4 个短标签（长句子仍会写坏）。
- 一组图按「总览 → 分层/架构 → 闭环/流程 → 具体环节」组织，正文每节配一张。

### 架构图类「精确图」的可靠套路（实测走通）

图像模型边规划边生图时，会往图里补它见过的通用组件（K8s / RAG / Vector DB / API Gateway…），
把真实系统画成一张通用云架构图。用户一句话点透：**让它自己写提示词，你只负责原样贴回去生图。**

1. **规划会话**：在**新会话**里只让它**写生图提示词**，明说「这一轮只写提示词，不要生图」，
   要求「一段一张、逐字可复制」。
2. **本机原样复制**这些提示词，贴到**另一个新会话**里生图——**不要贴回规划会话**，
   否则它带着失败历史重新加工，又回到加戏的老路。一个提示词一轮，出一张取一张。
3. 取回后验真，落盘命名带上轮次。

**抽象层级决定成败**：能画准的是**概念级**——三四个节点、每节点两三个短标签、一张画布一个主题。
5–6 级逐级链路图 + 十几处标签必崩。

### 要连续出十几张（PPT 逐页生图）走流水线

同样"让它在另一个会话里写提示词 → 本机原样贴回去生成"，但要**先要一份统一视觉规范**
（色号 + 字号层级 + 版式骨架），之后每页复用——这是十几页风格一致的关键。
节奏、四个必踩的坑和配套辅助函数见 `references/slide-image-pipeline.md` 与 `scripts/gen_helper.py`。

## 写文档：讲人话（用户偏好）

- 主线是**把故事讲好**：先给一个真实的、带结果的小故事（做了什么、抓到什么、代价是什么），再讲怎么做。
- 术语保留（MCP / OAuth / CDP 照写），但解释用大白话；不要堆砌工程腔。
- 附录只放「查表型」内容：命令速查、故障速查表、实测证据、产物清单。
- **背景 / 工具清单 / 调用链路 / 大坑必须留在正文**，不要推去附录——把技术内容全推附录会让
  正文只剩结论，读者知道「要这么做」却不知道「为什么有这些部件、它们怎么接起来、哪一步会摔」。
- 交付前做一次「初学者测试」：假装第一次看，逐段问「这个词是不是没解释就用了？这一步跳了吗？
  成功长什么样？」。原话：**问题往往不是说得不够简单，而是太简单了没说清楚**。
  配套要求：①每个专有名词首次出现就带一句解释（含它跟别的东西的关系）；②名词列成清单
  （是什么 / 在这里干什么 / 能不能换）；③讲清一次真实调用的完整时序；④坑单列一章，
  每个按「现象 → 为什么 → 怎么办」写。
- 每张配图配一句图注，用正文口吻复述图在说什么；图里的标签与正文用词保持一致。

## 交付「别人可以直接喂给 agent」的复现说明

用户会要求把操作说明写给**别人的 agent**（不是人）。出口是两个：Word 里单列一节，
**再加一份同目录的独立 `.md`**——agent 读 md 不必解压/解析 docx。骨架照
`templates/agent-runbook.md` 抄。要点：

- 判据必须**机器可判定**：写「页面里 `navigator.webdriver === false`」，不要写「确认浏览器正常」。
- 失败分支按**可观测信号**检索（报错原文、DNS 返回值、`aria-label` 的值、下载目录为空），
  让卡住的 agent 拿眼前现象直接对号，不必先理解原理。
- 变量单列一张表，区分「本机实测值」与「按你的环境替换」；不要把自己的绝对路径写成通用值。
- 硬约束放最前面（不动用户的浏览器、不索取凭据、不用粘贴冒充读取、只写新路径、哪两步必须交人工）。
- 收尾要有完成判据清单 + 交接要求（写状态文件：绑定关系、隧道地址、接入方式、验证结论、坑与处置）。

## 一劳永逸：开机自启 + 固定地址

「每次都要重新弄一次」的根因是 **quick 隧道地址每次重启都变**。三件事一次做完就基本不用管：

1. **专用浏览器实例自启**：用一个独立 user-data-dir + `--remote-debugging-port=<PORT>` 的
   **原生**浏览器实例承载登录态（不要用自动化框架自带方式启动：那些实例 `navigator.webdriver=true`，
   Google 会判「此浏览器或应用可能不安全」而拒绝登录）。
   持久化：macOS 用 LaunchAgent（`~/Library/LaunchAgents/*.plist`，`RunAtLoad`）；
   Windows 用任务计划程序登录时触发（或启动文件夹快捷方式）。见 `references/cross-platform.md`。
2. **桥/隧道自启 + 自愈**：定时跑 `c2c doctor -w <workspace>`（一切正常时是 **no-op**，
   地址不变，所以定期跑不会造成漂移）。macOS 用 LaunchAgent（`StartInterval`）；
   Windows 用任务计划程序（每 30 分钟一次）。
3. **固定域名（真正的解）**：只有 named tunnel 能让连接器 URL 永不变——
   `c2c tunnel choose -w <ws> --mode named --zone <域名> --json`（前置 `c2c tunnel login`，
   该步需要用户在浏览器里登录 Cloudflare；域名需托管在 Cloudflare）。换成功后重启只跑 doctor
   （`namedRepair`），**不用删连接器**。没有域名就只能留在 quick：重启机器 = 删连接器重建 + 重新配对。

先查状态：`c2c tunnel status -w <ws> --json`（`preference` / `loggedIn` / `zone`）。

## 浏览器操作要点

本机踩过的坑（输入法、坐标、附件、发送判据、超时、多标签）全部整理在
**`references/browser-pitfalls.md`**——动手操作页面前先读它，尤其这四条最常见的：

1. **`browser_exec` 的 IPC 默认只等 5 秒**：重页面/导航会报 `timed out after 5s waiting for the daemon`，
   看着像卡死，其实只是超时。解：attach 出 `sessionId`，再用
   `cdp("Runtime.evaluate", session_id=sid, expression=…, returnByValue=True, _response_timeout=40)`
   —— 参数名是 **`_response_timeout`**（写 `response_timeout` 会被当成 CDP 参数丢掉，无效）。
2. **先分清"页面卡死"还是"通道超时"**：先 `js("1+1")`；轻页面正常而目标页 evaluate 超时 →
   页面没加载完，**第一嫌疑是代理/梯子没开**。
3. **点击坐标一律用 `getBoundingClientRect()` 的 CSS 像素**，不要照截图量
   （截图像素 = CSS 像素 × `devicePixelRatio`）。
4. **输入框必须用 `form div[contenteditable="true"]` 精确定位**，绝不用 `div[contenteditable]`：
   长会话里每段提示词自己也是可编辑块，会命中历史消息——话全打进旧提示词，真输入框一直空着，
   没有报错，`innerText.length` 看着还"对"。

## “无法加载此回复” / “无法加载 ChatGPT 模型”（2026-10 实测，不是封号不是限流）

症状：消息发出去了（页面上能看到自己那句），但回复位只显示「无法加载此回复」，或者顶部报「无法加载 ChatGPT 模型」。
**先别重发**。实测的真相：

- **服务端的回复已经生成并保存**。同一会话里**刷新一次页面**（`Page.reload`）后，回复就完整显示出来（实测两次都这样，包括一段 400 字的三条提示词）。
- 因此：下次遇到这个提示，先 `Page.reload` 再读 `document.body.innerText`，能直接把回复抓走；不要重发（重发只会多一条失败记录，还可能加深风控）。
- 成因侧写：这台机器访问 chatgpt.com 走本地代理，代理节点当天对 chatgpt.com 返回 **403**；**流式（wss）响应最容易在中间被断**，前端拿不到就渲染成“无法加载”。HTTP 页面加载往往仍正常，所以看起来“一半能用”。
  排查一行命令：`curl -s -o /dev/null -w '%{http_code}' -x http://127.0.0.1:7892 https://chatgpt.com/`.
- **另一个放大因素：反复新开标签页**。每开一个新标签都重启整个 Web 应用、重新握手；实测演示中连开 3 个会话来发消息后，失败率明显上升。**固定用一个会话标签**，不要每次新开。
- 与“Unusual activity”区分：那个才是反自动化提示，由 DOM 级写入（`Input.insertText` / `execCommand`）触发；本条纯属前端渲染失败。


## 生图提示词：**别替它加规格，你加了就会变丑**（2026-10-15 实测，用户纠正）

用户原话：**「你看我给他的提示词，是让他自己判断啊，它的能力很强的，你控制太多反而丑」**。

实测对照（同一批图，同一个主题）：

- 我在它的提示词里加满 `#123B69` 色号、`1.5–2px` 线宽、图例不超过画面 9%、节点顺时针摆位……
  出来的图**机械、模板感强**，用户评价「太幼稚」。
- 去掉这些约束、只锁语义（逐字中文标签、关键箭头方向、不编造数据）后，它用自己的最新生图模型出图，
  **质量明显更高**：会自己加坐标系、阶段对照表、图例、低饱和配色，版面也更像真论文 Figure。

**分工定死**：

| 该锁死（语义） | 该放开（美术） |
|---|---|
| 逐字的中文标签、关键箭头方向、不编造数据/不把候选画成已落地 | 色号、线宽 px、字体名、图例高度百分比、节点摆角、版面骨架 |

**“可用标签”也是限定（2026-10 被连训两次）**：写“可用标签：提问 / 模型 / 一段回答”
或用“构图核心是一条直路、没有执行环节”描述画面，都算替它画图。分享人原话：
“**你给 gpt 只传达，不要限定啊，只给核心主题，让他自己思考放什么图合适**”。

正确写法：**页面标题 + 这页要立的判断 + 用在哪里**，然后住手：

```
第 1 张 —— 用在《大模型会说，但不等于能干活》这一页。
这一页要做的是左右对比：左边是「问一句、答一段，执行还是靠人」，
右边是「给一个目标、多步做完、产物能被验收」。要几张、怎么画、画什么，你定。
```

注意：中文标签逐字约定、不能编数据这两条属**语义硬要求，可以留**；
构图、标签清单、图例、色号、线宽、张数一律不给。写错了就明确说“上一条的标签和构图要求作废，按你的判断来”——它会接受并重做。

另一个实用经验：**同一个图位它会给多个变体**（实测一个「Agent 执行反馈」图位给了 6 个）。
全部取回、拼成联系表看一眼，挑最干净的那个，不要拿第一张就用。

**但「新下载的哈希」≠「它最后一轮给的图」**（踩过）：同一会话里它先给过一批变体，后一轮才用最新模型重出；
两批混在一起，按哈希去重会把旧变体也一起存下来，很容易拿错（实测把旧变体当成 F01 贴进了 PPT，
用户一眼就看出“你贴的是旧的”）。
**正确判据是 DOM 位置**：把 `img[src^="blob:"]` 连同 `getBoundingClientRect().y + scrollY` 取出来，
**y 值最大/最靠下的那一组（同一 y 区间、间距均匀的几张）就是最后一轮的消息里的图**；
y 为负或明显更小的属于更早的消息。先按位置分批，再按哈希去重，最后拼联系表选题。


## 让它评审成品：给 PDF，不给一堆截图（实测有效）

用户会说「**你给他 PPT**」。正确做法是把**成品 PDF 挂进对话**（不是逐页截图，也不是源码）：

- **一个 PDF 附件它就能逐页翻看**，回复会按 `P1…P25` 给逐页意见，还会引用 PDF 的页面尺寸、字号作依据
  （实测它会自己看出“正文 11–15pt 偏小”“第 12 页的③跑到下一行”这类具体缺陷）。
- **联系表 / 拼版图只在看“图片本身”的风格问题时挂**（生图风格反馈）；成品评审用 PDF，挂多张反而会被附件上限截断。
- **要它给的不是美学评论，而是可执行的改版清单**，逐页四件事：
  ① 现在最突出的问题（一句话）；② 改成什么版式骨架、分几个区、每区放什么；
  ③ 哪些内容该删、哪些移到讲稿；④ **这张页唯一要留下的判断**。
- 再要它定**全局规则**：强调手段最多叠加几种、表头/灰底什么时候用、每页要点上限、正文字号下限。
  把这三条拿回本机写进生成脚本，比逐页改字省得多。
- 挂文件的做法见下面「挂文件有可靠路子」；一次挂 1–2 个附件（挂完记得确认输入框附件列表已被清空 = 已发出）。

**它的建议要过滤，不要全盘接受**（用户原话：「**不一定全盘接受，比如第一面没必要改啊，那个是我们的封面**」）：

- **用户固定的模板件**（封面、目录、机构页）它不了解背景，改成它的口味等于弄坏用户的既定件；动手前先问“哪几页是既定的不能动”。
- **稿子自带的样式元素**（如页底橙色结论条）它可能因为“每页都出现”而建议删——那不是缺陷（那是参考稿的样式），
  改法是让它只说结论、**不复述正文**，而不是取消。
- 它指出的**字号偏小、灰底过度、配图被挤小、同一信息在一页说两遍**这类问题通常是真问题，照做。

**长回复会在生成中被页面重载打断**（页面只剩一行「无法加载此回复」）：只要正文渲染过一次，
就能用 `document.body.innerText` 把整段抢救出来存盘（按回复的起始句切到 `回答已完成`），**不要重发**——
它那一轮往往已经写完了大部分。

**用户可能自己就在同一个标签页里跟它对话**：读 DOM 时会把用户的话一起读进来（`你说：…`），
那是用户的真实输入（例如他在反驳它的封面建议），**不要当成自己的任务，也不要替它回**；照用户的结论办就行。


## 连接器只读 + 隧道假活（2026-10-15 实测，都踩过）

- **连接器没有写接口**：让网页端「把成果写进工作区文件」必然失败（它自己会报只有读取/搜索/状态检查接口），
  它会改成在聊天里给一个附件卡片。**别指望点「下载」落盘**——实测点完 `~/Downloads` 里没有东西，
  CDP 的 `Browser.setDownloadBehavior` 也无效（该控件不是真 `<a>`，是个 `span[role=link]`）。
  **可靠取法：点开那个文件卡片，它会把全文内联渲染进页面**，`document.body.innerText` 随之涨十几 K，
  切出来即可（起点是那行 URL 编码的文件名，终点是 `回答已完成`）。
- **发消息会「看着发出去了、其实没发」**：页面里消息文本与「你说：」计数会短暂变化，随后回退。
  **发送后必须隔几秒复核「你说：」计数仍为 +1**；只查输入框是否清空不够。
- **空态新对话的输入框是 `<textarea>`，插入内容后才升级成 ProseMirror contenteditable**：
  所以发第一条消息前 `div[contenteditable]` 会返回空；`Input.insertText` 本身可用
  （React 一两秒后接管），但**点发送前必须查发送按钮的 `disabled`**。
- **长提示词在全新对话里可以直接 `Input.insertText` 一把写完**：实测 500–700 字的中文提示词（生图提示词那一类）
  一次写入，读回 `innerText.length` 与发送按钮 `disabled === false` 都正常，发送后照常出图；
  逐字符真键是**长会话**里的保底手段，不是首选。判据始终是**发送按钮的 disabled 状态**（React 认得这份文本才会亮）。
- **挂附件失败就止损**：合成的假粘贴会造出「上传未成功」的坏附件（见 `references/uploading-files-to-web-chatgpt.md` 的
  "试过但不生效的做法"）。挂附件这一环**最多两轮**，仍不成就先把成品交给用户、说明审查待补——
  实测那两轮里失败卡片会一直挂在那儿，继续纠缠只会把交付往后拖。
- **MCP 端点回 530 而 `doctor` 报隧道正常**＝有个**僵尸 cloudflared**（`pgrep -fl cloudflared` 看启动日期是几天前的）。
  `pkill -f "cloudflared tunnel"` 再跑 `doctor` 拉起新进程，公网立刻恢复 401；**不要**因此删连接器重建。


## Pitfalls

| 现象 | 原因 | 怎么办 |
|---|---|---|
| doctor 报绿但网页端调用 401 | 连接器指向已死的旧地址，doctor 的记账已漂移 | 用一次真实 `workspace_info` 验证；按 `references/bridge-setup.md` 的重连流程**删连接器重建** |
| 授权页 `authorization request has expired` | OAuth 授权请求**只能提交一次**，用 JS 直接写 `input.value` 会把它消耗掉却不带配对码 | 真实点击输入框 + 逐字符真键输入配对码 + 真实点击 Connect；过期就重新 `c2c pair` |
| 页面只有 `Retry` / `重试` | 导航错误，不是生成中，也不是配对失败 | 同标签重试一次；仍不行就回到本线程上一个可用对话 URL，再点页面上的「打开…项目」链接 |
| 连接器「重新连接」点了没反应 / 页面卡在无法访问 | 旧地址已死，Reconnect 无效 | **删掉该连接器重建**（同名前缀、新地址），再配对 |
| 点了下载按钮但下载目录没有新文件 | 该控件走系统保存对话框，自动化环境下不落盘 | 不要反复重试点击；改从页面里 `fetch` 图片/文件字节再分块读回（`references/media-export.md`） |
| 附件粘贴后发送按钮是灰的 | 文件还在后台上传 | 轮询到 `aria-label==='发送'` 的按钮 `disabled === false` 再点发送 |
| agent 反应像卡住，其实它还在读文件 | 长回复分段流式写 | 用"最后一段长度稳定"判完成，不要按"你说："计数 |
| agent 启动专用浏览器被拒（`blocked by policy`）/ 宿主没有浏览器控制接口 | 首次接入的最后一步需要"点页面"，策略受限环境给不了这个能力 | **首次接入**改走 `references/bridge-setup.md` 里的**手动路径**（不需要调试端口、不需要自动化权限，人用自己的浏览器点几下）。但要清楚：整套协作的"手"就是浏览器控制——日常协作仍然需要它，缺了就退回"人当打字员" |
| 本地模型/本地端点请求卡死 | 系统代理把 `127.0.0.1` 的请求也劫走 | 设 `NO_PROXY=127.0.0.1,localhost,::1` 并在脚本里 unset 代理变量 |
