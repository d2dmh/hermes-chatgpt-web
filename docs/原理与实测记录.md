# 原理与实测记录（人读的）

> 这份文件回答两个问题：**为什么必须是"网页端出方案 + 本机执行"这个分工**，
> 以及**哪些说法是真在本机跑出来的**。数字都来自一台 Apple M5 / 16GB / macOS 27.0.1 的笔记本，
> 配中国网络环境（家用宽带 + 本地代理）。

## 一、分工不是设计出来的，是被否出来的

最初的做法很自然：让本机 agent 自己规划、自己动手。结果反复翻车在同一类地方——
**它会在"该由模型判断"的地方自己拍板，然后越拍越偏**：

| 它自己拍板的东西 | 后果 |
|---|---|
| 字号、配色、每页几条要点 | 交五轮否五轮（用户原话：「你根本不用限定这么多啊……你还在乱指挥干啥」） |
| 技术路线（换转换器、从头手搓版式） | 白烧好几轮，最后仍然回到"先要方案"这条路 |
| 架构图里该出现哪些组件 | 往图里补 K8s / RAG / 向量库——那是它见过的通用云架构，不是我们的系统 |

反过来，**把"出主意"交给网页版 ChatGPT、本机只负责执行与核验**之后，同一批任务一次就过：

- 只发一句需求（一篇论文 + "要 5 张科研 PPT 配图"），它自己规划出
  「先核对论文方法与数据 → 研究背景 / 耦合框架 / 情景设计 / 主要结果 / 结论与局限」，
  并在首轮自己发现"五页拼版不符合一页一张完整图片"，主动改成逐页生成。
- 要求它"交付前以独立审查专家身份自审一遍"之后，它连续驳回了自己 3 批图：
  引入源文件里不存在的组件、擅自加入 CLI/API Clients、把 CDP 画成走固定隧道。
  **没有把废稿冒充成成品。**

所以本仓库的 skill 里，两条规矩的优先级最高：

1. **先交材料再动手**：收到任务（尤其是材料文件）先要一份可实现的方案，再执行。
2. **只传背景与需求，不要替它下限定**：版式/字号/颜色/字数这类规格是它的专业范围，你写了反而更差。

## 二、为什么要 MCP 桥，而不是复制粘贴

一开始是"把材料粘贴进聊天框"。这条路的问题是结构性的：

- 粘贴是有损的——大文件会被截断，图片贴进去会变成缩略图；
- 粘贴会污染它的判断——它会对着你手写的摘要做规划，而不是对着事实；
- 反过来，它的产出要人工搬回本地，闭环就断了。

桥（只读 MCP）把这件事变了：网页端**自己读**工作区里它需要的那几行文件，控制消息保持在 1 KB 以内。
本机 agent 只发"目标 / 范围 / 限制 / 成功标准"，不再搬运内容。

代价是这套东西有"基础设施"：隧道、OAuth、配对码、连接器。所以本仓库把首次接入写成了
给 **agent 读的**步骤（`skills/chatgpt-web-planning/references/bridge-setup.md`），
人只需要在浏览器里完成两次登录。

## 三、实测证据清单（可复现）

| 说法 | 证据 |
|---|---|
| 网页端能真的读到本机文件 | 在工作区写入 `Verification: <随机串>`，让它用连接器读回，与本机 `cat` 逐字符一致；它自报读取方式是连接器的 `read_file` |
| 它生成的图是模型原始产出，不是截图 | PNG 里有 C2PA 出处块：`OpenAI OpCo, LLC` / `dname=ChatGPT` / `version=gpt-image` / `digitalSourceType=…/trainedAlgorithmicMedia`；截图或重新编码不会有这些。用 `scripts/verify_asset_origin.py` 一条命令验证 |
| 页面上那张图能被逐字节取回 | 页面里 `fetch(blobURL)` 拿到的字节数 == 落盘文件字节数；多张图按 sha256 去重筛新图 |
| 固定域名真的解决了"重启就失效" | 配 named tunnel 之后 `pkill -f "cloudflared tunnel"` → 自检 → 隧道以**同一地址**重建，连接器无需重建 |
| 定时自愈不会造成地址漂移 | 同一命令连跑两次都返回"无修复项"，地址不变 |
| 一个任务一个对话是必要的 | 长对话里它开始重复、混淆上一轮结论；新对话（自包含首条消息）后恢复准确 |
| 输入框必须用逐字符真键事件 | `execCommand('insertText')` / CDP `Input.insertText` / 直接赋值 都会出现"看着进去了、发送按钮不出现"；逐字符 `keyDown`+`keyUp` 稳定 |

## 四、这套东西的边界（什么时候别用）

- **一步小操作别叫它**：简单问答、改一个文件名，直接做。为仪式感等一轮是纯浪费。
- **需要精确图形的地方**（要按真实组件画架构图）：图像模型会加戏，得走
  "让它只写生图提示词 → 另开新会话原样贴进去生成"的三步法（见 SKILL.md）。
- **别把审计当免检**：自审能拦住大部分错，但本机仍要逐条核对。
  本仓库把"验真脚本 + 组件清单逐条核"写成了必做步骤，就是为了不给自己留侥幸。
- **别人家的浏览器别动**：协作浏览器是**用户可见的窗口**，agent 动手前必须把自己的标签切到前台，
  否则键鼠会落到用户正在看的页面上。

## 五、诚实标注：哪些没验证过

- **Windows 一列**（`references/cross-platform.md`、Windows 的剪贴板挂附件做法、
  任务计划程序自启）是按 Windows 官方文档与 PowerShell 语义写的，**没有在真机跑过**。
  第一次装完请把实际结果回填进去。
- 隧道/代理相关的经验来自中国网络环境；换到别的网络下，"代理没开导致页面打不开"
  这类现象可能不出现，也不排除出现别的。
- 上游桥（c2c）的 Windows 分支与 Windows 版内置浏览器行为，本仓库不做承诺——出问题先
  `c2c doctor`，再照上游 `docs/troubleshooting.md` 处置。
